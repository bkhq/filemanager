## Context

Gap review against Google Drive (2026-11-02): delete is permanent, no search, uploads silently rename on conflict, no undo, no details, no new-file / duplicate, preview has no navigation. All items below work on top of the existing `Driver` interface.

## Design

### Trash (router-level, driver-agnostic)

- `Mount.trash?: boolean` (default off; a git worktree mount would not want a hidden folder). `MountInfo.trash` tells the UI.
- Storage: `/.fm-trash/<id>/<name>` plus `/.fm-trash/<id>.json` `{ path, name, kind, size, deletedAt }`, written through the same driver, so memory / local / S3 all work. Drivers must create missing parents on `move` (added to the contract suite).
- The trash folder is invisible to every regular route: hidden from listings of `/`, and any path inside it answers 404.
- `ops delete` moves to trash when the mount has trash, unless `permanent: true`. Results carry `trashId`.
- `GET /m/:mount/trash` lists items whose original path the caller may read.
- `POST /m/:mount/trash/restore { ids }` moves items back (`write` on the original path; name clash -> `a (1).txt`).
- `POST /m/:mount/trash/purge { ids? }` removes items (`delete` on the original path); no ids = empty trash.

### Other server additions

- `list?q=` filters direct children by case-insensitive name substring before sorting and paging.
- `GET /m/:mount/usage?path` returns `{ bytes, files, dirs, truncated }`, walking at most `archiveMaxEntries` entries.

### Client / UI

- Upload: tasks carry `conflict`; before enqueueing, top-level names that clash with the current listing open a dialog (replace / keep both / skip, applied to all clashes). Folder uploads keep merging with `rename`.
- Undo: a snackbar after delete (restore from trash), move / rename (inverse move) and copy (permanent delete of the copies).
- Details side panel toggled from the toolbar / context menu; folder size via `usage`.
- New text file (empty write with `conflict=fail`, then open it) and duplicate (copy into the same folder, `rename`).
- Trash view: a "Trash" node under each trash-enabled mount; restore / delete forever / empty trash.
- Preview: prev / next buttons and arrow keys across files of the current listing; click-to-zoom for images; previewers report unsaved changes via `onDirtyChange`, and closing or navigating asks before discarding.
- `editable` prop (default `true`).

## Out of scope

Recursive search, retention / auto-purge, sharing and versions (managed store, P2), thumbnails, marquee selection, mobile layout.
