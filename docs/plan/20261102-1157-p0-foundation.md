## Proposal

### 1. Scaffold

- Bun workspace root: `package.json` (workspaces `apps/*`), `tsconfig.base.json`,
  ESLint (antfu config, as in bkd/bithk), repo hygiene files
  (`.gitignore`, `.gitattributes`, `.editorconfig`, `LICENSE` MIT, `README.md`,
  `.env.example`, `.bun-version`), `git init`.
- `registry/fm/**` is plain source (not a workspace package), resolved by the
  demo apps through the `@/fm/*` alias — the exact path a host gets after
  `shadcn add` into `src/fm/*`.
- `registry.json` with items (P0): `fm-core`, `fm-server`,
  `fm-driver-local`, `fm-client`, `fm-react`; each lists `dependencies`
  (npm) and `registryDependencies` (shadcn primitives + sibling fm items).
  `bun run registry:build` → `shadcn build` → `public/r/*.json`.
- Quality gate `bun run check`: lint + typecheck + test + registry build +
  registry install smoke test.
- Runtime guard: ESLint `no-restricted-imports` (`node:*`, `bun:*`) and
  `no-restricted-globals` (`Bun`, `process`, `Buffer`) on
  `registry/fm/{core,server,client}/**`.

### 2. `fm/core`

```text
registry/fm/core/
  schema.ts   zod: Entry, EntryCaps, DriverCaps, MountInfo, ListQuery/Result, OpsRequest/Result, ErrorBody
  path.ts     normalize / join / dirname / basename / isInside (POSIX, rejects NUL, "..", backslash)
  errors.ts   FmError(code, status): NOT_FOUND 404, FORBIDDEN 404 (fail-closed), ETAG_MISMATCH 409,
              EXISTS 409, TOO_LARGE 413, UNSUPPORTED 405, INVALID 400
```

### 3. `fm/server`

```text
registry/fm/server/
  driver.ts     Driver interface (architecture §3.2, P0 subset: stat/list/read/write/mkdir/move/copy/remove)
  router.ts     createFileManager({ mounts, authorize, audit?, limits }) → Hono app
  archive.ts    streamed zip (fflate ZipPassThrough), caps 5000 entries / 2 GiB
  mime.ts       extension → MIME table, inline-safety rule
  contract.ts   driver contract suite: runDriverContract(name, makeDriver) for bun:test
```

Routes (P0): `GET /mounts`, `GET /m/:mount/{stat,list,read}`,
`PUT /m/:mount/write`, `POST /m/:mount/{mkdir,ops,archive}`. Upload in P0 is
`PUT /m/:mount/write` streaming the body (limit-checked); sessions come in P1.
Every handler: resolve mount → normalize path → `authorize(ctx, action,
target)` → driver call → `Entry` with `caps = driver.caps ∩ authorize`.

### 4. Drivers

`registry/fm/drivers/{memory,local,s3}.ts`, all implementing `Driver` from
`fm/server/driver.ts` and passing `runDriverContract`.

#### `local` (Bun)

Port of bkd jail logic: resolve inside root, `realpath` of target (or nearest
existing parent) must stay inside root; atomic writes (`tmp` + `rename`);
`etag = mtimeMs-size` (weak); `If-Match` compared before write; options
`{ root, readOnly?, showHidden?, gitIgnore? }`. Trash deferred to P1.

#### `s3` (Bun + Workers)

SigV4 signing over `fetch` (`aws4fetch`); `{ endpoint, bucket, region,
accessKeyId, secretAccessKey, prefix?, forcePathStyle? }`. Dirs are common
prefixes plus zero-byte `dir/` markers for empty folders; `etag` = object
ETag; move/copy = CopyObject (+ delete) per object, bounded per request;
recursive delete via ListObjectsV2 + DeleteObjects; Range reads pass through.
Contract suite runs against a MinIO sibling container.

### 5. `fm/client`

`createFmClient({ baseUrl, fetch? })` with typed methods per route;
TanStack Query hooks `useMounts`, `useList` (infinite, cursor), `useStat`,
mutations with cache invalidation; `uploadFile` via XHR for progress
(pattern from bithk `upload-queue.ts`) + a small zustand upload store.

### 6. `fm/react`

```text
registry/fm/react/
  use-file-manager.ts   headless: path/history, selection (click / ctrl / shift range), sort, view mode,
                        clipboard (cut/copy/paste), keyboard map
  file-tree.tsx         virtualized, lazy-expanded
  file-list.tsx         list + grid, virtualized, rubber-band select, drag-to-folder move
  breadcrumb.tsx, toolbar.tsx, batch-bar.tsx, context-menu.tsx, name-dialog.tsx, conflict-dialog.tsx
  upload-queue.tsx, drop-zone.tsx
  preview/registry.ts   registerPreviewer({ match, component, priority })
  preview/{image,text,pdf,fallback}.tsx   text/code via CodeMirror (read + edit with etag conflict)
  file-manager.tsx      composition: tree + list + preview pane
  locales/{en,zh}.json
```

Visibility of every action is gated by `entry.caps` / mount caps only.

### 7. Demo

- `apps/demo-api` (Bun + Hono): mounts `memory` ("Scratch") and `local`
  rooted at `./.tmp/demo-root` (seeded); `authorize` allows all, plus a
  read-only mount to exercise caps.
- `apps/demo-web` (Vite + React + TanStack Router + shadcn base-nova): one
  route rendering `<FileManager />`. Dev URLs via nsl, run under tmux.

### 8. Tests

- `bun:test`: core path/schema unit tests; contract suite for memory + local;
  local security tests (`..`, absolute path, symlink escape, NUL); router tests
  (fail-closed 404, If-Match 409, Range 206, unsafe-inline MIME, archive caps).
- Vitest + Testing Library: `use-file-manager` selection/clipboard logic,
  preview registry matching.
- Playwright e2e against the demo: browse, upload, rename, move, delete,
  preview image/text/pdf, read-only mount hides write actions.
- Registry smoke: build registry, `shadcn add` all items into a temp Vite
  app under `.tmp/`, run `tsc --noEmit`.

## Risks

- shadcn registry for server-side files: items use `registry:lib` /
  `registry:file` with explicit `target`; the host's alias config must match.
  Mitigated by the install smoke test.
- Copy distribution has no automatic upgrades; hosts diff on re-add. Keep
  files small and stable.
- Workers compatibility is only lint-enforced in P0; the real Workers build
  arrives with `demo-worker` in P1 and may surface API gaps.
- `local` etag from mtime+size can miss same-size edits within mtime
  resolution; acceptable for P0, documented.
- PDF preview: native `<iframe>` vs `pdfjs-dist` — start with native embed
  (no dependency), revisit if mobile rendering is required.

## Scope

New repo, roughly 60–80 files: scaffold/config (~15), `registry/fm` (~35),
demo apps (~12), tests (~15). No changes to bithk or bkd.

## Alternatives

- Build on SVAR File Manager (MIT) instead of own UI: faster start, but its
  styling and state model fight the shadcn copy model and caps-gated actions.
- npm packages instead of registry: easier upgrades, rejected by decision §0.
- Path-in-URL routes (bkd style) instead of `?path=`: prettier URLs but needs
  marker parsing and encoding edge cases; rejected.

## Annotations

- 2026-11-02: approved. Backends are implemented as **drivers** behind one
  `Driver` interface (`registry/fm/drivers/<name>.ts`); a new backend is a new
  driver file plus a contract-suite run. The `s3` driver (SigV4 over `fetch`)
  moves into P0; multipart upload sessions stay in P1.
- 2026-11-02: delivered. Deviations from the proposal:
  - `ETAG_MISMATCH` answers 412 (HTTP precondition semantics), not 409.
  - `local` driver `gitIgnore` option deferred to P3 (bkd migration).
  - File tree is lazy but not virtualized; the list / grid are virtualized.
  - The driver contract suite is its own registry item (`fm-driver-contract`)
    so `fm-server` stays free of `bun:test`.
  - `fm/react` imports `cn` from shadcn's `cn` package: shadcn does not rewrite
    `@/lib/utils` for custom-registry files (caught by the registry smoke test).
  - Registry items reference each other through the `@fm` namespace.
  - Demo without router and test tooling: see `docs/decisions/001`, `002`.
  - S3 contract verified against RustFS (MinIO images not pullable).
