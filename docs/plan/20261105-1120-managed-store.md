# 20261105-1120-managed-store Managed store (generic, phase 1)

- **status**: draft
- **createdAt**: 2026-11-05 11:20
- **relatedTask**: 20261103-0508-managed-store (phase 1 of 3; bithk adapts to this design later, no bithk compatibility layer)

## Context

- Drivers today map real storage 1:1 (local, s3, r2, memory). Trash is router-level (`/.fm-trash` via `move`), rename on S3 is copy + delete, search walks folders, there is no dedupe and no history.
- Architecture §3.2 / §6 plan a `managed` driver: a database tree over content-addressed blobs stored through another driver, SQLite (Bun) or D1 (Workers).
- `FmDriver`: `stat / list / read / write / mkdir / move / copy / remove`, optional `search`, `multipart`. The router owns trash, uploads, archive, thumbnails.
- Constraints: Web-API only (the host passes the database); D1 has no interactive transactions (batches only); Web Crypto cannot hash incrementally.

## Decisions (from the discussion)

- Generic design; bithk adapts later.
- Database access through **Drizzle** (`drizzle-orm`, sqlite-core schema shared by `bun:sqlite` and D1).
- Isolation by a host-chosen **namespace** string (user, team, project…); one mount = one namespace.
- **Versions**: keep the last N per file (default 20, configurable; 0 = off).
- **Stars / recent** stay with the host (`meta` prop); no star table.

## Proposal (phase 1)

1. **Schema** (`registry/fm/managed/schema.ts`, Drizzle sqlite-core) + SQL migration file:
   - `fm_entries` (id, namespace, parent_id, name, kind, blob_id, size, mime, etag, created_at, updated_at, deleted_at, deleted_from) — unique live name per (namespace, parent_id, name).
   - `fm_blobs` (id, sha256, size, storage_key, ref_count, created_at) — unique sha256.
   - `fm_versions` (id, entry_id, blob_id, size, etag, created_at).
2. **`managedDriver({ db, namespace, blobs, versions? })`** implementing `FmDriver`:
   - write: stream to a temporary blob key while hashing with an incremental SHA-256 (`@noble/hashes`, Web-API only); known hash → drop the temp object and reference the existing blob ("instant upload"), else move it to `sha256/<aa>/<hash>`. Overwrite pushes the old blob to `fm_versions` (trimmed to N).
   - move / rename / copy are row updates (copy shares blobs: O(rows), no bytes copied).
   - search via SQL (`LIKE` on names below a folder; fuzzy ranking reuses `fuzzyRank` on SQL candidates).
   - multipart: delegated to the blob driver when it has one, then hashed on completion.
   - Statements ordered so a failure never leaves a live row without a blob; D1 runs them as batches.
3. **Driver-native trash and versions** (router extension, opt-in per driver):
   - `FmDriver.trash?` (`remove → soft delete`, list / restore / purge); the router uses it instead of `/.fm-trash` when present — same routes and UI.
   - `FmDriver.versions?` (list / read / restore) + routes `GET /m/:mount/versions?path`, `GET /m/:mount/versions/read?path&id`, `POST /m/:mount/versions/restore`.
   - `collectGarbage(db, blobs)` exported: deletes blobs with `ref_count = 0` and expired trash (also usable from cron).
4. **Registry**: new item `fm-managed` (`managed/schema.ts`, `managed/driver.ts`, `managed/migrations/0001_init.sql`), dependencies `drizzle-orm`, `@noble/hashes`.
5. **Demo**: `apps/fm-api` adds a "Managed (SQLite)" mount (`bun:sqlite` file under `.tmp/`, blobs on a local driver); `apps/fm-worker` optional D1 binding smoke via `wrangler dev`.

6. **Version pin and versions UI** (added 2026-11-06 for the drive variant, plan `20261106-0700-drive-variant` phase 4):
   - `fm_versions.pinned` (boolean, default false). Trimming to the last N skips pinned versions; `FmDriver.versions.pin(path, id, pinned)` and `POST /m/:mount/versions/pin { path, id, pinned }`.
   - `FmMountInfo.versions: boolean`; client `versions(mount, path)`, `versionUrl(mount, path, id)`, `restoreVersion(...)`, `pinVersion(...)`.
   - Details panel (both variants): a "Versions" section on mounts with versions: date, size, pinned marker; actions download, restore (asks for the change message like other writes), pin / unpin.
   - Dependencies at their latest stable versions (checked 2026-11-06): `drizzle-orm` 0.45.4 (1.0 is still a release candidate), `@noble/hashes` 2.4.0.

Not in phase 1: quotas computed by the store, sharing, bithk adapter / migration (phase 3, bithk side).

## Risks

- Biggest change since P0: new storage model, router extension points, two SQL backends. Mitigation: the existing driver contract suite runs against managed (bun:sqlite + memory blobs), plus managed-specific tests (dedupe, versions trim, trash restore / purge, GC, crash-safe ordering) and a D1 run through miniflare.
- Hashing cost on large uploads (single pass, streamed; no buffering).
- Orphan temp blobs after a crash: GC removes temp keys older than a day.
