## Context

- 86d4883 / a1ddd40 put the image preview (`react/media-stage.tsx`) on `react-zoom-pan-pinch` 4.2.0 (wheel, trackpad and pinch zoom, drag to pan, double-click toggle). Before that, zoom only grew the image inside a scrolling box, which is why panning by drag did not work.
- Reproduced in Chromium with generated images (2400x1600, 6000x4000, 1000x3000):
  - dragging pans, keys `+` / `-` / `0` zoom once per press, arrow keys still step to the previous / next file: fine;
  - **zoom ceiling**: `maxScale={4}` is relative to the fitted size, so a 6000x4000 image (fit 17%) stops at 43% after 20 zoom-ins and its details are never shown at real size;
  - **viewport**: the `TransformWrapper` sits inside a box sized to the fitted image (`layoutOf`), so the zoomed view is clipped to that box; a 1000x3000 image stays in a 228 px wide column of a 1000 px wide stage.
- Leftovers of the old zoom: `FmMediaView.zoom`, `clampZoom`, `ZOOM_STEP` and `layoutOf`'s zoom branch are no longer driven by the UI; the image cursor stays `zoom-in` even when zoomed. `apps/fm-web` declares `^4.2.0` while the repository pins exact versions (registry: `react-zoom-pan-pinch@4.2.0`).
- Library choice (npm, 2026-11-07): `react-zoom-pan-pinch` 4.2.0 (MIT, ~3.8 M weekly downloads, updated 2026-09) is the React standard for this and already handles pinch, trackpad and inertia. Alternatives: `@panzoom/panzoom` 4.6.2 (MIT, framework-agnostic, ~0.65 M; would need our own React glue), `yet-another-react-lightbox` 3.33 (MIT, a full lightbox with a zoom plugin; replaces our dialog and toolbar), `openseadragon` 6.1 (BSD, tiled deep zoom for gigapixel images; heavy, needs tiles). Keep `react-zoom-pan-pinch`.

## Proposal

1. **Stage-wide viewport**: the `TransformWrapper` fills the stage; its content is the fitted, rotated / flipped image box, centred. Zoom and pan then use the whole preview area for any aspect ratio, and rotation keeps working on the content.
2. **Real-size zoom**: `maxScale` = the larger of 4x fit and 4x real size (`max(4, 4 / fit)`), so every image reaches at least 400% of its pixels; `minScale` stays at fit.
3. **Percentage button**: shows the real-size percentage (as today) and toggles between fit and 100% (real pixels) instead of only resetting; `0` still fits.
4. **Cursor**: `zoom-in` at fit, `grab` / `grabbing` while zoomed.
5. **Clean-up**: drop `FmMediaView.zoom`, `clampZoom`, `ZOOM_STEP` and the zoom branch of `layoutOf` (unit tests follow); pin `react-zoom-pan-pinch` to `4.2.0` in `apps/fm-web`.
6. **Tests**:
   - unit: `layoutOf` without zoom, the max-scale helper;
   - e2e (generated PNGs): a 6000x4000 image reaches 100% via the percentage button and further with zoom in; dragging moves the image while zoomed; a tall image's zoomed view spans the stage width; the existing "rotates, flips and zooms" test keeps passing (updated only where the button now toggles).

## Risks

- The content box changes shape on rotation; the wrapper is reset on rotate so bounds stay right.
- Hosts with vendored copies get the change with the next `shadcn add`; no prop or export changes.

## Scope

`registry/fm/react/media-stage.tsx`, `registry/fm/react/transform.ts` (+ test), `apps/fm-web/package.json`, `bun.lock`, `tests/e2e/fm.spec.ts` (image test), new e2e cases, changelog.

## Verification

`bun run check`; full e2e including the new image cases; `registry:smoke`; screenshots of a wide, a tall and a huge image zoomed to 100%.

## Alternatives

- **Switch to `yet-another-react-lightbox`**: richer lightbox, but it replaces the preview dialog, toolbar and plugin previewers.
- **`openseadragon`**: right for gigapixel scans with tiles; overkill for previews.

## Annotations

- Added while implementing: zoom buttons and `+` / `-` multiply by 1.5 around the view's middle (`zoomAround` in `transform.ts`), because the library's `zoomIn(step)` adds to the relative scale and barely moves large images (100% to 106% in three clicks). The step expectations in `fm.spec.ts` went from 125% to 150%.
- While zoomed, arrow keys pan (the library's keyboard handling); at fit they still step to the previous / next file.
