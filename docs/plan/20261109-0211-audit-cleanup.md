## Context

A repository audit for duplication and legacy leftovers found no compatibility layer. It did find unused code and stale docs. bkd (the only adopter, vendored at `86d4883` without local changes) was checked: it does not use `registerPreviewer`, the three labels or the `trash.ts` helpers. It does use `TRASH_DIR` and `purgeExpired`, which stay.

## Proposal

1. Delete `registerPreviewer`; previewers are added through `FmPlugin.previewers` only. Make the built-in list read-only.
2. Delete the labels `folderName`, `newName` and `rotateLeft` (en and zh).
3. Stop exporting `trashedPath`, `moveToTrash`, `getTrashItem`, `listTrash` and `dropTrashItem`.
4. Rename the `fm-demo:*` localStorage keys of `apps/fm-web` to `fm-web:*` (no migration: development only).
5. `docs/architecture.md`: remove `<AttachmentList />` and Slots, describe `actions` and plugin previewers, RustFS instead of MinIO, mark bkd as adopted and `fm/managed` as not implemented.
6. ADR 001: `apps/demo-web` becomes `apps/fm-web`.
7. Sync task statuses: five tasks already `[x]` in the index, and `bkd-pilot` (bkd PR #162 merged). `plugin-followups` stays open.

## Risks

Hosts on `registerPreviewer` would break on their next upgrade; no known host uses it. Bithk has not adopted the registry.

## Scope

`registry/fm/react/preview-registry.ts`, `registry/fm/react/labels.ts`, `registry/fm/server/trash.ts`, `apps/fm-web/src/app.tsx`, `tests/e2e/fm.spec.ts`, `docs/`.

## Verification

Lint, typecheck, unit tests, and the e2e flows that use the renamed keys.

## Alternatives

Extracting the shared UI of the two shells was deferred by the user.
