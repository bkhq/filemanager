## Context

Depends on recursive search ([plan](20261103-1005-recursive-search.md)): `GET /m/:mount/search` and `FmDriver.search?`. bkd opens files by name across a git work tree (it uses `git ls-files`). Keyboard handling in `registry/fm/react/file-manager.tsx:358` (`onKeyDown`); the local driver is `registry/fm/drivers/local.ts:45` (Bun-only, may spawn processes).

## Proposal

- `search` route gains `mode=fuzzy`: fuzzy match on the relative path, ranked server-side — contiguous match > basename match > path match, then shorter path; returns the top `limit`.
- Ranking is a pure function in `registry/fm/core/fuzzy.ts` (`fuzzyScore(query, path)`), no new dependency; shipped in `fm-core`.
- `localDriver({ gitIgnore?: boolean })`: when true and the root is a git work tree, `search` lists candidates with `git ls-files --cached --others --exclude-standard` (one spawn, cached per request), else the bounded walk.
- UI: `Ctrl/Cmd+P` opens a quick-open dialog (`react/quick-open.tsx`): input, keyboard navigation (Up / Down / Enter / Esc), Enter previews a file or opens a folder; a toolbar button for touch.
- Labels for en / zh; `features.search` hides it.

## Acceptance

- Unit tests for `fuzzyScore` ordering.
- Router / driver test with a temporary git repo fixture (ignored file excluded, untracked file included).
- e2e: `Ctrl+P`, type part of a nested name, Enter opens the preview.
- `bun run check` and `bun run test:e2e` pass.

## Risks

- `git` must exist on hosts that enable `gitIgnore`; without it, fall back to the walk.

## Scope

`core/fuzzy.ts` (new) + test, `server/router.ts`, `drivers/local.ts` + test, new `react/quick-open.tsx`, `react/file-manager.tsx`, `react/labels.ts`, `registry.json` (new files), `tests/e2e/fm.spec.ts`.

## Alternatives

- A fuzzy library (fzf-style): better ranking, extra dependency in shipped code.
