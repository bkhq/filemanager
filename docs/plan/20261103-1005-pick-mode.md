## Context

bkd needs workspace attachments and bithk "import from drive". `<FileManager>` already supports `features` / `readOnly` (`registry/fm/react/features.ts`, `VIEW_ONLY_FEATURES`), `layout="single"` and selection (`react/state.ts:1-77`). Props are at `react/file-manager.tsx:82-117`. No server change is needed.

## Proposal

- `<FilePicker>` in new `react/file-picker.tsx`: `{ baseUrl? | client?, mounts?: string[], initialMount?, initialPath?, accept?: string[], multiple?: boolean, maxTotalSize?: number, onPick(entries: FmEntry[]), onCancel?() , labels? }`.
- Built on `FileManager` with view-only features, single layout and a new internal `pick` prop: double-click / Enter on a file toggles or confirms instead of previewing; a bottom confirm bar shows the count and total size; Confirm is disabled when nothing is selected or the total exceeds `maxTotalSize` (with a message).
- `accept`: extensions (`.png`) and MIME globs (`image/*`); non-matching files render disabled and cannot be selected; folders stay navigable. Matcher `acceptsEntry(entry, accept)` exported from `react/file-picker.tsx` (or a small pure module) with unit tests.
- `mounts` filters the visible mounts client-side.
- Demo route or toggle in `apps/fm-web` to exercise it; labels en / zh; register the file in `registry.json` (`fm-react`).

## Acceptance

- Unit tests for the accept matcher.
- e2e: pick one file, pick several with `multiple`, a rejected type is disabled, size cap shows the message.
- `bun run check` and `bun run test:e2e` pass.

## Risks

- Adds a mode flag inside a 960-line component; keep the change behind the `pick` prop so normal mode is unchanged.

## Scope

New `react/file-picker.tsx` (+ test), `react/file-manager.tsx`, `react/file-list.tsx`, `react/labels.ts`, `registry.json`, `apps/fm-web/src/app.tsx`, `tests/e2e/fm.spec.ts`.

## Alternatives

- A separate picker list component: no flag in `FileManager`, duplicates browsing logic.
