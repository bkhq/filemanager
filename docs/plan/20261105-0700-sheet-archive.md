## Context

- `fm-plugin-sheet` (`plugins/sheet-view.tsx`, `parse.ts`): CSV / TSV via papaparse, XLSX via read-excel-file; every cell becomes a string; rows capped at 1 000 and all rendered; read-only; XLSX dates use `toLocaleString()` (time shown even for plain dates).
- Archives: the router can build zips (`archive.ts`, download of a selection) but cannot look inside one; a `.zip` previews as "No preview available".
- Drivers support ranged reads; `DecompressionStream("deflate-raw")` is a Web API on Bun and Workers.

## Proposal

### Sheet plugin
1. Typed cells: numbers (XLSX numbers, CSV cells that parse as numbers) right-aligned with tabular digits; XLSX dates shown as dates (`toLocaleDateString`, time only when not midnight); booleans as-is.
2. Virtualized rows (`@tanstack/react-virtual`, already in fm-react): no 1 000-row cap; sticky header and row numbers stay. Up to the existing 20 MiB file size.
3. CSV / TSV editing when the entry is writable: double-click or Enter edits a cell (Enter / Tab commit and move, Esc cancels), "Add row" at the end, row context menu "Delete row". Header shows Save / Discard while dirty; Save writes with `If-Match` (412 → conflict message with Overwrite / Reload, like the text editor); unsaved edits ask before closing via `onDirtyChange`. Delimiter and line endings of the source are kept (`Papa.unparse`). XLSX stays read-only.

### Archive browsing (zip)
4. Server (Web-API, `server/zip.ts` + router):
   - `GET /m/:mount/zip/entries?path` → `{ entries: { path, size, compressedSize, mtime, dir, encrypted }[], truncated }`, read from the central directory with ranged reads (EOCD in the last 64 KiB, Zip64 supported), capped at `limits.archiveMaxEntries`.
   - `GET /m/:mount/zip/read?path&entry=&download=` streams one entry (stored or deflate via `DecompressionStream`), same content-type safety as `/read`; encrypted or other methods → 415.
   - Authorized like `read`; the archive must be within `limits.archiveMaxBytes`.
5. `fm-plugin-archive` (new registry item): previewer for `.zip` (and `.jar`, `.apk`, `.docx`-style zips only when named `.zip`/`.jar`): a collapsible folder tree of the entries with size and date, a filter box, click a file to preview it inline (text / image through the existing previewers using the entry URL) or download it; "Download" for the whole archive stays in the header.
6. Client: `zipEntries(mount, path)`, `zipEntryUrl(mount, path, entry, { download })`. Labels (en / zh), README, demo seed gets a small `samples/archive.zip`.

## Risks

- Large central directories: capped by `archiveMaxEntries`; `truncated` is shown.
- Zip bombs: entries are streamed, never buffered; sizes come from the directory, previews only for text / images under the existing preview caps.
- tar / tar.gz / 7z / rar are out of scope (no random access); they keep the download fallback.

## As built

- Sheet: `parse.ts` keeps typed XLSX cells (`FmSheetCell`), `isNumeric`, `cellText` (UTC dates without midnight time), CSV format (`delimiter`, `newline`, `trailingNewline`) and `serializeCsv`. `sheet-view.tsx` renders a `role=table` grid of fixed 160 px columns with virtualized rows (no row cap), sticky header / row numbers, cursor (click, arrows), editing (double-click / Enter / F2; Enter / Tab / Esc), Add row, row-number context menu Delete row; Save / Discard in the header while dirty, `If-Match` against the version the edit started from, 412 → Overwrite / Reload; `onDirtyChange` for the close guard. XLSX read-only.
- Archive: `server/zip.ts` (`readZipEntries`, `openZipEntry`; EOCD scan of the last 64 KiB, Zip64 EOCD, Zip64 extra field, stored / deflate via `DecompressionStream`), routes `/zip/entries` and `/zip/read` (archive within `archiveMaxBytes`, entries capped by `archiveMaxEntries`, `/read`'s content-type safety). Encrypted / other methods answer 405 (`UNSUPPORTED`, the existing code) instead of the planned 415. `fm-plugin-archive` (`archive.ts`, `archive-view.tsx`, `archive-tree.ts`): virtualized folder tree with implicit folders and sizes, filter, inline text (≤ 1 MiB) / image preview, download per entry, summary and truncation note. Demo seed has `samples/archive.zip` (fresh roots only).
