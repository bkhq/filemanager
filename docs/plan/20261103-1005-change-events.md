## Context

Hosts need to observe mutations: bithk records an audit actor per change, bkd refreshes git status and session context. Today nothing is emitted. Mutating routes in `registry/fm/server/router.ts`: write 399-436, mkdir 437-450, ops (delete / rename / move / copy) 451-522, trash restore 632-657, trash purge 658-684. Per-item results already go through `settle` (212-230). Options type `FmRouterOptions` is at 58-67. `router.ts:152` JSDoc still names `createFileManager`.

## Proposal

- `FmRouterOptions.onEvent?: (c: Context<E>, event: FmChangeEvent) => void | Promise<void>`.
- `FmChangeEvent` (exported from `server/router.ts`, `Fm` prefix per naming rules):
  `{ op: "write" | "mkdir" | "delete" | "move" | "copy" | "rename" | "restore" | "purge"; mount: string; path: string; to?: string; trashId?: string; ok: boolean; error?: { code: string; message: string } }`.
- Fire once per item after the driver call, for successes and failures. Delete into trash reports `op: "delete"` with `trashId`. Batch ops fire per item in request order.
- Awaited, but errors thrown by the hook are caught and logged (`console.error`), never change the response.
- Fix the `router.ts:152` comment to `createFmRouter`.
- Document the hook in `docs/architecture.md` §3.3 and the README server example.

## Acceptance

- Router tests assert the exact event sequence for each op, including partial failure in a batch, trash delete, restore, purge, and that a throwing hook does not change the response.
- `bun run check` passes.

## Risks

- Hook latency adds to request time (awaited by design so hosts can write audit rows transactionally).

## Scope

`registry/fm/server/router.ts`, `registry/fm/server/router.test.ts`, `docs/architecture.md`, `README.md`.

## Alternatives

- Fire-and-forget (not awaited): lower latency, but audit writes can be lost on Workers when the request ends.
