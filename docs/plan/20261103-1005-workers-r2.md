## Context

Workers compatibility of `core` / `server` / `client` / non-local drivers is enforced only by lint (`eslint.config.ts`, `no-restricted-imports` / globals). The driver contract is `registry/fm/server/contract.ts` (`runDriverContract`). `apps/fm-worker` is planned in `docs/architecture.md` §3.0. Wave 2; ideally after resumable uploads so R2 implements multipart once.

## Proposal

- `registry/fm/drivers/r2.ts`: `r2Driver({ bucket: R2Bucket, prefix? })` over the Workers binding — list with delimiter and cursor, `get` with range, `put` (multipart for large bodies when the multipart capability exists), copy via get + put, delete recursive. New registry item `fm-driver-r2`.
- `apps/fm-worker`: wrangler config, Worker entry mounting `createFmRouter` with an R2 mount, serving the built `fm-web` assets.
- Tests: run `runDriverContract` for R2 under miniflare / `@cloudflare/vitest-pool-workers` or `wrangler dev` (whichever runs with bun test most simply; record the choice); a CI job runs it.
- Dependencies: `wrangler`, the chosen test runtime, `@cloudflare/workers-types` (dev only), latest versions verified at implementation time.

## Acceptance

- Driver contract green on R2 locally and in CI.
- `apps/fm-worker` builds (`wrangler deploy --dry-run`) and serves the same UI under `wrangler dev`.
- `bun run check` and `bun run registry:smoke` pass with the new item.

## Risks

- New dev dependencies and a CI job (risk areas: dependencies, CI config).
- No real Cloudflare deploy in this campaign (outward-facing).

## Scope

`registry/fm/drivers/r2.ts` (+ test), `registry.json`, `apps/fm-worker/*`, `package.json` / `bun.lock`, `.github/workflows/ci.yml`, `eslint.config.ts`, README, `docs/architecture.md`.

## Alternatives

- S3 API against R2 with the existing `s3` driver: works today, no binding; keeps credentials in env instead of a binding.
