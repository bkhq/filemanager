## Context

- The list / grid (single layout, search results) shows every entry of the folder; only the name filter (`q`) and the hidden / git-ignored toggles narrow it. The split layout shows the tree and a preview, no list.
- `kindOf` (`react/state.ts`) knows dir / image / video / audio / pdf / text / archive / other; no sheet / document / code split.
- There is no host hook for per-user metadata; bithk keeps starred and recent in its own database, bkd has none.

## Proposal

1. **Filters**, applied client-side to the loaded entries:
   - Type (multi-select): folder, image, video, audio, document (pdf, doc/docx, odt, ppt/pptx, rtf), sheet (csv, tsv, xls/xlsx, ods), code / text, archive, other. A `filterKindOf(entry)` next to `kindOf`, unit-tested.
   - Modified: any, today, last 7 days, last 30 days, this year.
   - UI: a "Filter" dropdown (checkbox items for types, radio items for modified) in the list toolbar and in the tree header's More menu; a row of removable chips under the toolbar while active, with "Clear". The tree applies the type / modified filter to file rows only (folders stay so you can navigate). Persisted per mount under `storageKey`.
   - Empty result shows "No items match the filters" with Clear.
2. **Host metadata** (optional prop): `meta?: FmMeta` with
   - `starred?(): Promise<FmRef[]>`, `setStarred?(ref, starred): Promise<void>`;
   - `recent?(): Promise<FmRef[]>`, `touch?(ref): void` (called when a file is opened);
   - `FmRef = { mount: string; path: string }`.
   When provided: tree sections "Starred" / "Recent" above the drives (entries resolved with `stat`, missing ones skipped; click reveals the entry); "Add to starred" / "Remove from starred" in entry context menus; in the single layout the Storage menu gets "Starred" / "Recent", which open a list of those entries with their parent folder (like search results).
   - The demo implements `meta` on `localStorage` to show it working; the component ships no storage of its own.
3. Labels (en / zh), README section for `meta`.

## Risks

- Client-side filtering only sees loaded pages (500 per page); scrolling loads more as today. Documented.
- `stat` per starred / recent ref; capped at 50 refs per section.

## Scope

`registry/fm/react/state.ts` (+ test), `file-manager.tsx`, `file-tree.tsx`, `labels.ts`, a new `react/meta.ts` (types + hooks), `apps/fm-web/src/app.tsx` (demo meta), README, e2e, changelog.

## Alternatives

- Server-side type / date filters on `list` (`type=`, `since=`): exact with paging, but every driver must support it; can follow later behind the same UI.
- Custom date range for "Modified" (date pickers): left out for now.

## Verification

Unit tests for `filterKindOf` and the date predicate; `bun run check`; e2e: filter by type and date in the list, tree file filtering, chips clear, starred / recent sections and context-menu star via the demo meta.

## As built

- `react/filters.ts`: `filterKindOf`, `modifiedSince`, `applyFilters` (`keepFolders` for the tree), `parseFilters`; unit-tested. Per-mount persistence under `<storageKey>:filters:<mount>`.
- `react/filter-menu.tsx`: `FilterMenuItems` (type checkboxes, modified radios, Clear) and `FilterChips`. Filter button in the list toolbar; "Filter" submenu in the tree's More menu; chips under the list header (list layouts) or the tree header (explorer). Empty result: "No items match the filters" + Clear. The explorer no longer drops the open file when a filter hides it.
- `react/meta.ts`: `FmRef`, `FmMeta`, `useMetaEntries` (stat, max 50, missing refs skipped). Tree gains `sections` (Starred / Recent, own open state, not affected by Collapse all); host-list rows show the drive and parent folder next to the name (accessible name `name, Drive/folder`). Entry menus: Add to / Remove from starred. Opened files call `touch` and refresh Recent.
- Deviation: in the single layout Starred / Recent are submenus of the Storage menu (open like quick open) instead of a separate list view.
- Demo: `meta` on localStorage (`fm-demo:meta`).
- Verified: `bun run check` (250 tests), `registry:smoke`, e2e 72/72 (new: list filters + persistence + empty state, tree filters, starred / recent). Keyboard / driver-group / collapse tests account for the demo's host lists.
- Follow-up: configurable via `features.starred` / `features.recent` and per-user "Show starred / recent" toggles in the explorer More menu.
- Follow-up: host lists render hierarchically (section → drive → folders → entries; compacted chains; starred folders expandable).
