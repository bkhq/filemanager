## Context

- `fm-react` ships the drive files (`drive-shell.tsx`, `drive-nav.tsx`, `drive-ref-list.tsx`, 581 lines) and `file-manager.tsx` imports `DriveShell` for `variant="drive"`, so every host copies drive code. No npm dependency was added by the drive.
- Registry items already split optional parts (`fm-plugin-*`, `fm-driver-*`), each listing `@bkhq/fm-react` (or others) in `registryDependencies`. Plugin labels live in the shared `labels.ts`.

## Proposal

- `useFileManager(props, mode = "workspace")`: the mode reaches `useViewState`; the other hooks read `drive` from it as today. `FileManagerProps` loses `variant`.
- New `react/manager-frame.tsx` (in `fm-react`): the error / empty states, root container, change-message context and `ManagerOverlays`, used by both `FileManager` and `DriveManager`.
- New `react/drive-manager.tsx`: `DriveManager(props: FmDriveManagerProps)` (`FileManagerProps` without `layout` and `pick`) = `useFileManager(props, "drive")` + frame + `DriveShell`.
- `registry.json`: drive files leave `fm-react`; new item `fm-drive` (`drive-manager`, `drive-shell`, `drive-nav`, `drive-ref-list`) with `registryDependencies: ["@bkhq/fm-react"]`.
- Demo: `?variant=drive` renders `DriveManager`. README, architecture, changelog updated.

## Risks

- Hosts that already used `variant="drive"` from `main`: none (unreleased since this morning).

## Scope

`react/file-manager.tsx`, `react/use-file-manager.ts`, `react/use-view-state.ts`, new `react/manager-frame.tsx`, new `react/drive-manager.tsx`, `registry.json`, `apps/fm-web/src/app.tsx`, README, `docs/architecture.md`, changelog.
