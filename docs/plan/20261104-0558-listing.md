- `registry/fm/drivers/local.ts`: option `showHidden` (16) drops dotfiles in `list` (371) and search (186); option `gitIgnore` (25) only affects search (git ls-files) and `.git` writes (216).

## Proposal

- A6: list query `hidden=0|1` (default 1, unchanged API behaviour); with 0 the router drops names starting with "." (a driver configured with `showHidden: false` still never returns them). UI: tree toolbar toggle "Show hidden files" (default off), persisted under `\${storageKey}:hidden-files`; tree, list, path-bar pickers and search use it.
- B6: optional `ignored?: boolean` on `FmEntry` (schema + types). The local driver with `gitIgnore` marks list entries via one `git check-ignore -z --stdin` call per listing, hardened like the existing ls-files call (fsmonitor off, minimal env, literal pathspecs); failures mark nothing. List query `ignored=0|1` (default 1) drops ignored entries when 0. UI: toggle "Show git-ignored files" (shown only when a listing has `ignored` entries or the mount reports it), ignored rows dimmed when shown.
- Docs: architecture HTTP API, README local driver options.

## As built

- Router: `GET /m/:mount/list` and `GET /m/:mount/search` accept `hidden=0|1` and `ignored=0|1` (default 1). On list, `hidden=0` drops names starting with "." and `ignored=0` drops entries flagged `ignored`; the result carries an `ignored` count (taken before filtering, present only when > 0). On search, `hidden=0` drops results below any dot segment and `ignored=0` drops flagged entries; the fallback walk skips both subtrees.
- Schema: optional `ignored` on `entrySchema` and `FmDriverEntry`, optional `ignored` count on `listResultSchema`; the router passes the flag through only when `true`.
- Local driver: with `gitIgnore`, `list` marks entries via one `git check-ignore -z --stdin` call per non-empty listing (paths sent with a `./` prefix so names stay literal). It shares the `spawnGit` helper with the `ls-files` search: `core.fsmonitor=false`, `core.untrackedCache=false`, minimal env (`PATH`, `HOME`, `GIT_CONFIG_NOSYSTEM`, `GIT_TERMINAL_PROMPT=0`, `GIT_OPTIONAL_LOCKS=0`). A non-zero exit or spawn failure marks nothing.
- Client / hooks: `FmListParams` / search options take `hidden` / `ignored`; only `false` is sent (as `0`). `useListing` / `useSearch` take an `FmListFilter` that is part of the query key.
- UI: tree toolbar toggles "Show hidden files" (eye icon, default off, `${storageKey}:hidden-files`) and "Show git-ignored files" (git icon, default on, `${storageKey}:ignored-files`; shown while the current listing reports ignored entries or while ignored files are hidden). The filter applies to the list, tree, path-bar pickers, search and quick open. Ignored rows are dimmed (`opacity-60`) in the tree, list and grid. Labels in en / zh.
- Tests: 10 unit tests (router 4: list `hidden=0`, list ignored flag / count / drop, search walk filters, driver search filters; local driver 5: marks ignored entries, literal names, no work tree, no `gitIgnore`, repo `core.fsmonitor` not run; client 1: params sent only when off) and 1 e2e (toggle hidden files in the tree and the single layout's list). `bun run check`: 229 pass, 1 skip, 0 fail; e2e: 39 passed.
- Docs: `docs/architecture.md` HTTP API rows for list and search; README local driver options table.
