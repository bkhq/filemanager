# 20261105-0440-thumbnails Thumbnails and saving image edits

## Context

- The grid view loads every image at full size (`readUrl`), so folders of photos are slow and heavy.
- The image preview rotates / flips only on screen; there is no way to keep the result.
- `server/`, `core/`, `client/`, `drivers/` (except `local`) must stay Web-API only (lint-enforced).
- Bun 1.4 ships `Bun.Image` (decode, `resize`, `webp`), verified here: no dependency needed on Bun. Workers have the Cloudflare Images binding (`env.IMAGES.input(stream).transform({ width }).output({ format })`), which `wrangler dev` emulates locally.

## Proposal

1. **Server hook** (Web-API only): `createFmRouter({ thumbnail?: (c, { entry, width, read }) => Promise<{ body: BodyInit; type: string } | undefined> })`.
   - Route `GET /m/:mount/thumb?path&w=` with `w` in `128 | 256 | 512`, images only (MIME `image/*`, SVG excluded), source up to `limits.thumbnailMaxBytes` (default 32 MiB). `ETag` = entry etag + width, `Cache-Control: private, max-age=86400`, `304` on `If-None-Match`. Authorized like `read`.
   - No hook, not an image, too large or the hook returns undefined → `404`; the UI falls back to the full image.
   - `FmMountInfo.thumbnails: boolean` (hook configured); client `thumbUrl(mount, path, width, version)`.
2. **Implementations** as separate registry items:
   - `fm-thumbnail-bun` → `registry/fm/thumbnails/bun.ts`: `bunThumbnail({ quality? })` via `Bun.Image` → WebP. Used by `apps/fm-api`.
   - `fm-thumbnail-cloudflare` → `registry/fm/thumbnails/cloudflare.ts`: `cloudflareThumbnail(images)` via the Images binding. Wired in `apps/fm-worker` and smoke-tested with `wrangler dev`; if the local emulation does not work in this container, this item is dropped from the batch and noted.
3. **Grid view**: `<img src={thumbUrl(…, 256)}>` (lazy, `onError` → full image) when the mount reports thumbnails.
4. **Save rotation / flip**: in the image preview, a "Save" button appears once the view is rotated or flipped, only for writable PNG / JPEG / WebP files with `features.edit`. The browser re-encodes through a canvas (same MIME, JPEG / WebP quality 0.92) and writes with `If-Match`; a changed file shows the conflict message. Zoom is not saved.
5. Labels (en / zh), README (hook, both items), e2e.

## Risks

- Canvas re-encode drops metadata (EXIF) and recompresses JPEG / WebP; stated in the button tooltip and README.
- Thumbnail generation is CPU work on the API server; responses are cacheable and sizes are whitelisted.

## Scope

`server/router.ts` (+ tests with a fake hook), `core/schema.ts`, `client/client.ts`, `react/file-list.tsx`, `react/media-stage.tsx`, `react/previewers.tsx`, labels, `registry/fm/thumbnails/*`, `registry.json`, `apps/fm-api`, `apps/fm-worker`, README, e2e.

## Alternatives

- Client-side thumbnails (canvas from the full image): no server work, but still downloads every full image.
- Thumbnail cache on storage (`/.fm-thumbs`): faster repeats, but storage writes and invalidation; HTTP caching is enough for now.

## Verification

Router tests (hook called with width, whitelist, non-image / too large → 404, ETag / 304, authorize, mount info flag), unit test for `bunThumbnail` dimensions, `bun run check`, `registry:smoke`, e2e (grid uses `/thumb` and shows the image, save-rotated round trip changes the stored dimensions), `wrangler dev` smoke for Cloudflare.

## As built

- Router: `thumbnail?: FmThumbnailHook<E>` (`(c, { entry, width, read }) => { body, type } | undefined`), `GET /m/:mount/thumb` (`w` 128 / 256 / 512, raster images only, `limits.thumbnailMaxBytes` 32 MiB, ETag `<etag>-w<width>`, `private, max-age=86400`, 304); otherwise 404. `FmMountInfo.thumbnails`. Client `thumbUrl`.
- `fm-thumbnail-bun` (`thumbnails/bun.ts`, `Bun.Image` → WebP, declines narrow / undecodable images; lint and tsconfig carve-out like `drivers/local`) used by `apps/fm-api`. `fm-thumbnail-cloudflare` (`thumbnails/cloudflare.ts`, structural `FmImagesBinding`, generic over the Hono env) used by `apps/fm-worker` with `"images": { "binding": "IMAGES" }`; smoke-tested with `wrangler dev` (600×300 PNG → 256×128 WebP).
- Grid: `GridImage` uses the thumbnail when the mount has them, full image on error.
- Save: `MediaStage` gets `mime` + `onSave`; Save appears once rotated / flipped for writable PNG / JPEG / WebP (gated on `caps.write` like the text editor); canvas re-encode (quality 0.92), `If-Match`, 412 → conflict message. `ImagePreview` keys the stage by etag so a saved image starts upright. The preview dialog now takes the listing's copy of its entry so the new etag reaches it.
- Verified: `bun run check` (256 tests: router thumb routes, `bunThumbnail` dimensions), `registry:smoke`, fm-worker dry-run build, e2e 75/75 (grid thumbnail is 256 px wide; save-rotated round trip 60×30 → 30×60).
