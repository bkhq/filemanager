## Context

- `<FileManager>` today is a workspace / IDE presentation: explorer tree with Changes / Starred / Recent sections, an inline preview and editor pane (CodeMirror, drafts, `If-Match`), quick open, git-ignored and hidden toggles, change messages.
- Drive building blocks already exist: `FileList` list and grid views with thumbnails, sort header, virtualization and marquee selection (`react/file-list.tsx`); `DetailsPanel`; `TrashView` (bulk restore, empty, retention); host `meta` for starred / recent; type and modified filters (`react/filters.ts`); recursive search; resumable upload sessions and the upload panel; `PreviewDialog` (full-screen preview with sibling navigation, optional editing); host `actions` in context menus; `features`, `readOnly`, per-entry `caps`.
- `react/file-manager.tsx` is 2302 lines: lines 322-1400 hold state and commands (location, expanded rows, filters, sort, selection, clipboard, dialogs, pending folders, listing / search, meta, changes / review, mutations, upload queue, navigation, restore, drag and drop, paste), lines 1400-2302 the JSX (tree pane, toolbar, list or open file, details, dialogs). A second shell cannot be added without splitting it.
- Entries are path-addressed (`core/schema.ts` `entrySchema`: mount, path, name, kind, size, mtime, mime, etag, caps, ignored). Hosts with id-keyed data (bithk shares, versions, file references) have nothing stable to attach to; drive columns such as owner have no field.
- bithk's drive (from `docs/architecture.md` §1 and the gap table in `20261103-0508-backlog-proposals`): spaces (personal / team / project), grid and list with thumbnails, filter bar (type, modified, owner, source), batch actions, starred / recent, trash, quota, shares, versions with pin. Its UI code is not available here; the layout below follows common drive products and is adjusted once screenshots are provided.

## Proposal

### Phase 1: split without behaviour change, entry fields

1. **State hooks** (`registry/fm/react/manager/`), moved out of `FileManager` as they are, grouped by concern; each file stays under ~800 lines:
   - `use-location.ts`: location, history, `go` / `navigate`, restore of the last location, expanded tree rows.
   - `use-listing-state.ts`: sort, filters, query and search scope, hidden / ignored, pending folders, `entries`, `dir`.
   - `use-selection.ts`: selection, clipboard, open file, preview.
   - `use-changes.ts`: change queries, index, totals, review state, tree sections (meta lists included).
   - `use-commands.ts`: mutations, upload queue, dialogs, notices, undo, drag and drop, paste, download, context-menu items.
   - `use-file-manager.ts`: composes the above into one object (`FmController`) that shells read.
2. **`WorkspaceShell`** (`react/workspace-shell.tsx`, further split into `workspace-tree-pane.tsx` and `workspace-main.tsx` if needed): today's JSX, reading `FmController`. `FileManager` becomes `useFileManager(props)` + shell. No visual or behavioural change; the 85 e2e tests and unit tests are the guard.
3. **Entry fields** (`core/schema.ts`, `server/driver.ts`), both optional, passed through by the router:
   - `id?: string`: a stable id from drivers that have one (managed store, a bithk adapter), so hosts can key shares / versions by id while the protocol stays path-based.
   - `extra?: Record<string, string | number | boolean | null>`: host data for display (owner, shared). Not interpreted by the manager except through columns (phase 3).
   - Router test: a driver returning `id` / `extra` → list, stat and search responses carry them; contract suite unchanged.

### Phase 2: `variant="drive"`

```tsx
<FileManager variant="drive" baseUrl="/api/fm" meta={meta} />   // drive
<FileManager baseUrl="/api/fm" />                               // workspace (default)
```

`variant` only picks the shell and defaults; `features`, `readOnly`, `sidebar`, `actions`, `plugins`, `meta`, `labels` keep their meaning. Preferences are stored per variant (`${storageKey}:drive:*`) so both can share a `storageKey`.

`DriveShell` (`react/drive/`):

- **Navigation** (left, collapsible; a sheet on narrow containers): one item per visible mount ("spaces", honouring `sidebar.hidden` / `group`), then Recent and Starred (when `meta` provides them), Trash (current mount, when it has one). No folder tree.
- **Header**: breadcrumb (existing `PathBar`), search box (current folder, "everywhere below" toggle), grid / list toggle, primary "New" menu (folder, text file) and "Upload" menu (files, folder) gated by caps and features.
- **Filter chips** under the header: type and modified, reusing `FmListFilters`; a "clear" chip when any is set.
- **Content**: `FileList`, grid by default with thumbnails; double-click a folder opens it, a file opens `PreviewDialog` (sibling navigation; editing only when `features.edit` and the file is text). Recent / Starred show their entries across mounts as a list with a location column (new small `drive-ref-list.tsx`); opening reveals or previews.
- **Batch bar**: replaces the filter chips while anything is selected: count, Download (single file or zip), Cut, Copy, Delete, host `actions` that accept multiple entries, clear selection.
- **Kept as is**: context menus, details panel (side, toggled from the header), upload panel, drop and paste uploads, dialogs, undo notice, trash view.
- **Off in drive**: explorer tree and its sections, review / Changes, quick open, inline editor pane, hidden and git-ignored toggles. Change messages still apply when the host passes `changeMessage`.
- **Demo**: `apps/fm-web` `?variant=drive`.
- **Labels**: new strings in `enLabels` / `zhLabels` (spaces, new, upload, clear filters, n selected, location).

### Later phases (not in this plan)

3. Host extensions: `FmMount.quota`, host-defined space groups, a "Shared with me" navigation item backed by a host mount, `columns` rendering `entry.extra`, owner / source filters, a "Move to…" folder dialog.
4. Managed store phase 1 (`20261105-1120-managed-store`) with versions gaining `pinned`, then the versions UI in the details panel.

## Risks

- Phase 1 moves ~1100 lines of interdependent hooks; refs and effects ordering (e.g. `openChangeRef` set after `reveal`, restore before first render) can change subtly. Mitigation: move code verbatim in small commits, run unit tests and the full e2e suite after each step; no renames of behaviour.
- `FmController` may grow into a large untyped bag. Mitigation: typed per-concern sub-objects (`location`, `listing`, `selection`, `changes`, `commands`).
- Vendored copies in hosts (bks) see a large diff on the next `shadcn add`; the public API (`FileManager` props, exports) stays the same, so hosts only re-add. `registry.json` gains the new files.
- Drive preview in a dialog drops inline editing drafts UX; acceptable for drive, workspace keeps it.

## Scope

- Phase 1: `react/file-manager.tsx` (shrinks to composition), new `react/manager/*` and `react/workspace-shell*.tsx`, `core/schema.ts`, `server/driver.ts`, `server/router.ts` (pass-through only), `server/router.test.ts`, `registry.json`.
- Phase 2: new `react/drive/*` (shell, nav, header, filter chips, batch bar, ref list), `react/labels.ts`, `react/file-manager.tsx` (`variant`), `apps/fm-web/src/app.tsx`, `tests/e2e/drive.spec.ts`, README and `docs/architecture.md` §4, changelog.

## Verification

- Phase 1: `bun run check`; full e2e (85) unchanged and passing; router test for `id` / `extra`; `registry:smoke`.
- Phase 2: new e2e in `tests/e2e/drive.spec.ts` against `?variant=drive`: spaces navigation, grid default and toggle, double-click preview and sibling navigation, filter chips, batch bar (select several → zip download / delete / undo), Recent and Starred views, trash, narrow container (navigation sheet); full e2e and `bun run check` green.

## Alternatives

- **Branches inside `FileManager`** (`if (variant === "drive")` in the existing JSX): smallest diff now, but the file passes 2700 lines and every later change has to reason about both layouts. Rejected.
- **Separate `<DriveManager>` component with its own state**: clean UI but duplicates navigation, selection, uploads and commands. Rejected in favour of shared hooks.
- **Props-only preset** (`layout="single"`, grid, features off): no new UI; does not give navigation, batch bar or filter chips, so it does not look like a drive.

## Annotations

- Implemented as flat files in `react/` (`use-*.ts`, `manager-*.tsx`, `workspace-*.tsx`, `drive-*.tsx`) instead of a `react/manager/` folder, so moved code kept its relative imports. The controller is the flat union of the hook results (`FmController`).
- The listing with its context menus became `manager-list.tsx`, shared by both shells. The drive filter bar also holds the sort menu.
